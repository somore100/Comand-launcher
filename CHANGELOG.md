# Changelog

All notable changes to Command Vault are documented here. Format loosely follows [Keep a Changelog](https://keepachangelog.com/).

## Unreleased

### Added

* MCP server for AI assistants: `command-vault --mcp` runs a headless Model Context Protocol server over stdio (works from source, the AppImage and the packaged builds). An assistant can list the entries you allowed, run them (no window; exit code and output returned) and read a scheduled entry's last result. Nothing is exposed by default: tick "AI assistants" in an entry's Edit dialog to allow it. It cannot create, edit or delete anything, entries with administrator rights are never exposed, input values for `{{placeholders}}` are rejected if they contain shell syntax, and every AI run is logged to `mcp-log.txt`. Settings has a copyable config snippet for the assistant.
* macOS startup: "Run when the computer starts" now works on macOS for Command Vault itself and for individual entries (per-user LaunchAgents in `~/Library/LaunchAgents`).
* "+ Add many" can now set "Run at startup", a daily schedule time and administrator rights for the whole batch (admin approvals are asked per entry).
* Tests: GUI smoke tests that build every dialog against a real Tk (skipped without a display), and a GitHub Actions workflow (`tests.yml`) that runs the whole suite on Linux (under Xvfb), Windows and macOS.
* Automation helpers for scripts (`cvauto`): a small library Command Vault writes and keeps up to date so any Python script can drive a website (`cvauto.web()`: goto/click/fill/press/wait_text with alternatives and retries) or a desktop program (`cvauto.app`: launch, wait_window, focus, keys, type_text) on Linux (xdotool/X11), Windows (PowerShell) and macOS (osascript). The routine editor's generated scripts now use the same library. A new "\u24D8 Automation" button in the Edit Entry dialog explains it with copyable examples, the library folder and the Python to use.
* Program entries now match the OS: "AppImage / program" on Linux (also `.desktop` files), "App (.app)" on macOS (launched with `open`, picker scans /Applications) and "Program (.exe)" on Windows (`.exe`, `.lnk`, `.bat`). Existing AppImage entries keep working; only real `.AppImage` files get the extract-and-run startup treatment.
* README: architecture diagram (GitDiagram, generated 2026-11-05).
* Edit Entry dialog reorganized: Startup, Schedule, Stay logged in (browser profile), Administrator rights and Launch shortcut are collapsible sections that show their current state in the header, so the dialog is much shorter by default. The browser profile option now explains itself (a private folder where a bot's browser keeps its logins).
* Routines: a no-code way to automate a website or a Linux desktop program. A new "Web routine (no code)" entry type with a step editor (open a page, click a button or link, type into a box, press a key, wait for text, wait N seconds), reorder/duplicate/delete, and a per-step "If this fails" choice (stop and report with a screenshot, skip, or retry), an optional alternative to try when the first target isn't found, and a per-step time limit. One button sets up a private Playwright + Chromium environment in Command Vault's own folder; "Test run" shows the browser and its output so you can log in once (the entry's persistent browser profile keeps you logged in; no password goes in a routine). A "Record" button watches what you click and type in a real browser and turns it into steps (password boxes are skipped), and ready-made templates (including an Aternos-style server start and an "Open Firefox" one) give you a starting point. Desktop-program routines (start a program, wait for or focus a window, press keys, type text) use `xdotool` on X11. Routines are turned into an ordinary script, so Run, autostart and schedules work unchanged (scheduled/boot runs are headless).
* Leave Feedback (Settings -> Feedback). A form with report type, optional name, title and description, plus an opt-in "Include my computer specifications" checkbox that shows exactly what will be sent (OS, architecture, CPU, GPU, RAM, app version; no username, hostname or serials). Sent through a small relay you own (`examples/feedback_relay.gs`, a Google Apps Script that emails the support address, so no mail password is ever in the app), or, if no relay is configured or it fails, by opening the user's own email app with the report filled in. Subject format: `[Command Vault] [BUG] title`. Reusable: `cmdvault/feedback.py` + `feedback_dialog.py`.
* Administrator rights for entries that use `sudo` (Linux and macOS). A new "Administrator rights" option in the Edit Entry dialog: **Off** (default), **Ask for the password each run** (sudo's own prompt in a terminal; a small zenity/kdialog/macOS dialog for silent runs), or **Don't ask**. "Don't ask" never stores a password: when you save, your system's own password prompt (pkexec / macOS admin dialog) installs a sudoers rule in `/etc/sudoers.d/` that allows only the exact `sudo` commands written in the entry, or inside the script it points at, and runs then use `sudo -n` so a missing rule fails instead of hanging. The rule is validated with `visudo` before it is installed, refreshed only when the commands change, and removed when you switch the option off or delete the entry. Refused on purpose: wildcards/quotes/`$` in sudo arguments, `{{placeholders}}`, and commands or files your own user can modify (that would hand root to anything running as you). Works for scheduled and boot runs. On Windows (untested) "Ask" shows a UAC prompt each run and "Don't ask" registers a highest-privileges scheduled task after one approval. Untested on real Fedora/Pop!_OS/macOS.

## v1.7.0 — 2026-10-27

### Added

* "+ Add many": paste one command or script path per line to create several entries at once, with a live preview. Names come from the file name, or the parent folder name when several lines share a file name (e.g. `alpha/run.sh`, `beta/run.sh`); `Name :: command` or a tab sets a name explicitly. Category and run mode apply to the whole batch, and each entry can optionally run in its own script's folder.
* Failed scheduled runs are no longer silent. Scheduled runs now capture the entry's output and exit code. A nonzero exit shows a red ⚠ next to the entry's schedule time, is reported in the console (including failures that happened while Command Vault was closed, on next launch), and the new "Last run" button shows the exit code, time and the last 64 KB of output. The Windows version of this wrapper is untested.
* Persistent browser profile for browser-automation bots. A new per-entry option in the Edit Entry dialog gives a Playwright/Selenium script a profile folder that survives between runs, so it stays logged in instead of starting fresh each time. The folder's path is passed to the script in the `COMMAND_VAULT_BROWSER_PROFILE` environment variable, for the Run button (both modes), autostart, and scheduled runs. Leave the folder blank for an automatic per-entry one (outside the vault folder, so it isn't part of Export Vault), or pick your own; Reset deletes it, and deleting an entry offers to remove its automatic profile. A starter script is in `examples/playwright_bot.py`.
* Per-entry scheduling. Each entry can now be set to "Run on a schedule" — daily, or on chosen weekdays, at a specific 24h time — from the Edit Entry dialog. Registered with the OS scheduler (a per-entry `cron` line on Linux/macOS, a Task Scheduler task on Windows) rather than an in-app timer, so it fires even if Command Vault isn't open. The cron path only ever touches the single line it owns in your crontab (tagged with a per-entry marker comment) — everything else already in your crontab is read and written back untouched. Scheduled runs always execute silently in the background, regardless of the entry's Run Mode (there's no terminal to attach at an unattended run). The entry list shows a "Sched" column with the configured time when a schedule is active.
* Single-instance lock. A second launch (from autostart, a global hotkey, or just double-clicking the icon again) now asks the already-running instance to raise its window and exits, instead of starting a competing process that could double-register hotkeys or race on `commands.json`. Backed by an OS-level exclusive file lock (not a fixed port), so it can't silently fail open if something else happens to be using a particular port; the "raise window" signal itself goes over an OS-assigned ephemeral port and requires a per-run token written to a user-only (`0600`) lock file, so another local process — or another user on a shared machine — can't trigger it.
* Unit tests (`tests/test_main.py`, run with `pytest`) covering the data layer (normalize/load/save, atomic writes, `.bak` recovery), `resolve_exec_command`, placeholder extraction/filling, update-check version parsing, and the single-instance lock.
* macOS build workflow (`.github/workflows/build-macos.yml`), producing `.dmg`s for both Apple Silicon and Intel. Unsigned/not notarized for now, so Gatekeeper needs a first-run workaround -- documented in the README.
* Corrupted `commands.json` recovery. A malformed data file (partial write from a crash, bad manual edit, disk issue) no longer prevents the app from starting. It's quarantined as `commands.json.corrupted-<timestamp>`, the app warns you, and it now recovers from the automatic `commands.json.bak` (see below) instead of starting empty, if a usable backup exists.
* Atomic, backed-up saves. Every save now writes to a temp file and `os.replace()`s it into place, so a crash or power loss mid-write can no longer corrupt `commands.json` in the first place (previously the exact scenario the recovery above exists to handle). Each save also rolls the previous file to `commands.json.bak` first, which the recovery path above now uses.
* Export / Import vault. Settings → Data Storage now has "Export Vault..." and "Import Vault..." — cheap insurance before big edits or moving to a new machine. Import confirms before replacing anything, automatically backs up your current vault first, and re-registers hotkeys/autostart entries from the imported file on this machine.
* Auto-update check. Settings → Updates shows your current version and a "Check for Updates" button; by default the app also checks automatically about once a day and lets you know if a newer release is out. Can be turned off from the same section.

### Changed

* Internal: split the ~3,200-line `main.py` into a `cmdvault/` package (data layer, autostart, scheduling, single-instance lock, update check, terminals, placeholders, entry/settings dialogs, hotkeys/tray, main window). `main.py` is now just the entry point; behavior is unchanged. Tests now import and patch the individual modules.
* Replaced the placeholder padlock icon with the real Command Vault logo across `packaging/icon.png` / `icon.ico` / `icon.icns`, the system tray icon, and the app's own titlebar icon.

### Fixed

* Importing a vault now re-registers schedules (not just startup entries) with the OS, clears the startup/schedule registrations of the vault it replaces so removed entries stop running, and offers to re-approve imported "don't ask" administrator entries on this computer.
* Dialogs are now resizable (wider and taller, never smaller than their content needs or 320 px tall) and the main fields stretch with them.
* Dialogs opening too narrow, which cut off the right-hand side of fields and buttons (the scrolling area now takes the width of its content).
* UI no longer overflows small screens. The Edit Entry and Settings dialogs now scroll, with their Save/Cancel/Close buttons pinned at the bottom and the height capped to the screen; "Add many" caps its size and keeps its buttons visible. On the main window, "+ Add" / "+ Add many" are no longer clipped in a narrow window (the search box shrinks instead), the list's scrollbar stays visible, and list columns can shrink. Escape closes these dialogs.
* App-level "run on startup" doing nothing on the AppImage build. Autostart was launching the AppImage directly from the `.desktop` file's `Exec=` line, which has to FUSE-mount itself right as the desktop session starts — a well-known race against DBus/`XDG_RUNTIME_DIR` not being up yet. Autostart now runs through a wrapper script that uses `--appimage-extract-and-run` (sidesteps FUSE for that one launch), defensively re-applies the executable bit, and adds a short startup delay that isn't GNOME-specific. Applied to both the app-level autostart and per-entry AppImage-type autostart entries.
* Entries launched via "Run" inheriting Command Vault's own `APPIMAGE`/`APPDIR`/`ARGV0`/`OWD` environment variables when Command Vault itself is running as an AppImage. A launched script or app that happens to also check `APPIMAGE` would see it pointing at Command Vault's own binary, only when launched via Command Vault's Run button — not when run standalone. Those AppImage-runtime variables are now stripped from the environment of anything Command Vault launches.

## v1.5.0 — 2026-08-26

## v1.4.0 — 2026-08-25

The first release with the full accumulated feature set: categories and custom icons, multiline commands, `.sh`/`.bat`/`.ps1`/`.py`/AppImage auto-detection, terminal vs. silent run mode with a live console log panel, templated `{{name}}` commands, "Run All", app-level and per-entry autostart, global hotkeys (app-level and per-entry, with conflict detection and a system tray icon), a custom terminal picker, configurable data storage with migration, and "Pick Installed App". See `README.md` for the full current feature list.
